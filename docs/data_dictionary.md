# CollectWise AI — Data Dictionary

This document describes the primary SQLite tables generated by CollectWise AI.

| Table | Purpose |
|---|---|
| customers | Synthetic customer identity and risk information |
| accounts | Customer account details and account status |
| loans | Loan principal, outstanding balance, interest rate, and lifecycle status |
| installments | Scheduled repayment amounts, due dates, paid amounts, and status |
| contact_preferences | Preferred contact channel, permitted contact hours, and do-not-contact flag |
| delinquency_snapshots | Loan-level days past due (DPD) and arrears snapshots |
| collection_cases | Collection case status, delinquency, arrears, and priority score |
| contact_attempts | Collection contact history, channel, outcome, and compliance status |
| promises_to_pay | Customer repayment commitments and their status |
| payments | Payment amount, date, loan, and installment association |
| case_events | Collection case event history; reserved for event records |
| anomaly_labels | Labels identifying intentionally injected data anomalies |

## Important Field Definitions

- **DPD:** Number of days an overdue installment remains unpaid.
- **Arrears:** Total unpaid amount associated with overdue installments.
- **Outstanding balance:** Remaining loan balance after recorded payments.
- **Priority score:** Score used to help rank collection cases.
- **Do-not-contact:** Customer restriction used to skip contact generation.
- **Promise status:** Indicates whether a promise is pending, kept, or missed.
- **Anomaly label:** Ground-truth label identifying a deliberately introduced data issue.

## Data Relationships

- A customer can have an account and one or more loans.
- A loan has multiple installments.
- A loan can have multiple payments.
- A loan can have a delinquency snapshot and collection case.
- A collection case can have contact attempts and promises to pay.
- Anomaly labels identify records used in validation scenarios.
